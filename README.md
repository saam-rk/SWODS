# SWODS — See What Others Don't See

**Next.js · React · TypeScript · Supabase · PostgreSQL · PWA**

## At a glance

- Mobile-first, ES/IT/EN participant and administrator workflows for collaborative photo prompts, galleries and team stories.
- Client-side image processing, database access policies and revocable private memory links.
- Collective mosaic generation, presentation/reveal screens and automated unit, SQL-model and browser checks.

## Overview

An independent mobile-first photography prototype inspired by multilingual student exchanges in Hervás. This public portfolio edition is not an official, approved or sponsored Erasmus+ or FuTourUp! service. Participants follow short prompts, contribute privacy-processed photographs, curate team stories, and reveal a collective mosaic. The concept is intentionally non-competitive and designed to return attention to the place quickly.

> **Status: functional prototype, not piloted.** The local demo and automated checks work, but this application has not been used with the Erasmus+ group, deployed to a live Supabase project, or validated on participants’ physical devices. Do not treat it as an approved event service. Production and privacy gates are tracked in [`PRODUCTION_READINESS.md`](PRODUCTION_READINESS.md) and [`docs/LIVE_ACCEPTANCE_CHECKLIST.md`](docs/LIVE_ACCEPTANCE_CHECKLIST.md).

## What is included

- Next.js App Router application with strict TypeScript, Tailwind CSS, ESLint, Vitest, PWA manifest, and a production service worker.
- English, Spanish, and Italian participant, facilitator, presentation, reveal, and memory experiences.
- Anonymous participant joining, team assignment, onboarding, prompt capture, private gallery, moderation, story selection, mosaic generation, and final presentation.
- Client-side image resize/orientation correction and EXIF/GPS removal before private upload.
- Participant session validation, protected direct routes, Supabase Realtime phase following, polling/reconnect fallback, and offline-safe cached state.
- Seven-day, participant-scoped IndexedDB recovery for failed production uploads on the same browser.
- Email/password administrator authentication backed by active `is_admin` membership; the `HERVAS-ADMIN` code exists only when Supabase is not configured.
- Revocable 256-bit memory links that expire after 30 days by default. Tokens stay in URL fragments, only hashes are stored, and private assets receive 15-minute server-signed URLs.
- Production environment validation, security headers, liveness/readiness endpoints, CI, smoke checks, and operational runbooks.

Product and public-edition design decisions live in [`PRODUCT.md`](PRODUCT.md) and [`DESIGN.md`](DESIGN.md). Private brief/history documents are intentionally not redistributed. See [`docs/SECURITY.md`](docs/SECURITY.md) for the threat model and dependency limitations.

## Local demo

Requirements: Node.js 22.12+ and npm.

```bash
npm ci
npm run audit:publication
npm run dev
```

Open <http://localhost:3000> for the public landing page, then enter the participant utility at <http://localhost:3000/join>. With no Supabase variables, the browser uses isolated local demo data:

- participant code: `HERVAS`;
- administrator code at `/admin`: `HERVAS-ADMIN`.

Demo credentials are never accepted when Supabase is configured. For a local production-mode preview (without Supabase), run `npm run build:demo && npm start`; never deploy that build as a real event.

## Production configuration

1. Create a dedicated hosted Supabase project and enable anonymous sign-ins.
2. Apply migrations `001` through `009` in filename order, normally with `supabase db push --linked`. The former audit migration `006_production_hardening` is now `007_production_hardening` to avoid colliding with `006_production_security_memory_links`; test this sequence against staging first.
3. Treat [`supabase/seed.sql`](supabase/seed.sql) as a 1–5 October 2026 event template. Review the date, teams, prompts, join code, participants, and mosaic target before using equivalent production data.
4. Create separate email/password Auth users for administrators and bootstrap active `is_admin` participant rows as documented in [`docs/OPERATIONS_RUNBOOK.md`](docs/OPERATIONS_RUNBOOK.md).
5. Configure these hosting variables:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-public-anon-or-publishable-key
SUPABASE_SERVICE_ROLE_KEY=your-server-only-service-key
APP_RELEASE=your-commit-sha
```

`SUPABASE_SERVICE_ROLE_KEY` is required for the server-only memory-link resolver. It must never use a `NEXT_PUBLIC_` prefix or reach browser code.

6. Build and start behind HTTPS:

```bash
npm run validate:production
npm run build
npm start
```

Production builds fail closed when required Supabase configuration is absent, local/insecure, or uses a key in the wrong role.

## Event flow

1. Sign in at `/admin` with a provisioned administrator identity.
2. Confirm the event configuration, participants, teams, localized prompts, final target, and story count.
3. Advance from welcome to exploration. Joined participant devices follow phase changes automatically.
4. Move to selection for team story curation, then presentation for `/present`.
5. Generate the mosaic, enable visibility, and move to reveal for `/reveal`.
6. Move to finished. In the Final admin section, create and copy a revocable 30-day private memory link.

If an upload fails, the processed photograph is retained privately in that participant's IndexedDB for up to seven days. Reopening the same prompt restores it for retry; successful upload or cancellation removes the pending copy. This is same-browser recovery, not cross-device or background synchronization.
